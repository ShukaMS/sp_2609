# 本物のごはんマッチを動かす設定手順(Supabase)

所要時間:30分ほど。1人が担当すれば大丈夫です。
設定が終わるまでは、アプリはこれまでどおり「デモモード」(ダミーの相手)で動きます。

## ファイルの役割

| ファイル | 中身 |
|---|---|
| `supabase-setup.sql` | データベースの作成と、北大メール限定などのルール。Supabase に1回貼り付けて実行する |
| `config.js` | Supabase の接続先。ここに2つの値を貼ると、本物のマッチになる |
| `cloud.js` | ログイン・プロフィール・誘い・メッセージ・写真の処理 |

---

## 1. Supabase のプロジェクトを作る

1. https://supabase.com を開き、「Start your project」→ **GitHub アカウントでログイン**
2. 「New project」を押す
   - Name:`nokorimono-club`(何でもOK)
   - Database Password:自動生成でOK。**どこかにメモしておく**
   - Region:**Northeast Asia (Tokyo)**
3. 「Create new project」を押し、1〜2分待つ

## 2. データベースを作る(SQLを貼るだけ)

1. 左のメニューの **SQL Editor** を開く
2. 「New query」を押す
3. `supabase-setup.sql` の中身を**全部コピーして貼り付け**、右下の **Run** を押す
4. 下に「Success. No rows returned」と出ればOK

> 何度実行しても壊れないように書いてあります。エラーが出たら、そのメッセージを Claude に貼ってください。

## 3. ログイン用のメールに「確認コード」が入るようにする

このアプリは、メールに届く **6桁の数字** でログインします。初期設定のメールにはリンクしか入っていないので、数字を足します。

1. 左のメニューの **Authentication** → **Emails**(または Email Templates)を開く
2. **Magic Link** を選び、「Body」の中身を次のように書き換えて **Save**
   ```html
   <h2>のこりものクラブ ログインコード</h2>
   <p>アプリに次の数字を入力してください:</p>
   <p style="font-size:28px;font-weight:bold;letter-spacing:4px">{{ .Token }}</p>
   <p>心当たりがない場合は、このメールを無視してください。</p>
   ```
3. **Confirm signup** も同じ内容にして **Save**(初めてログインする人には、こちらのメールが届くことがあります)

## 4. メールが届く相手について(大事)

Supabase の標準のメール送信には、次の制限があります。

- **プロジェクトのメンバーのアドレスにしか届きません**
- **1時間に数通まで**しか送れません

ハッカソンのデモでは、次のどちらかで対応してください。

- **かんたんな方法(おすすめ)**:Supabase の **Organization の Team** に、チーム全員を**北大のメールアドレスで**招待する(各自、北大アドレスで Supabase アカウントを作って参加)。デモに使うスマホは、**発表の前にログインを済ませておく**(一度ログインすれば、しばらくログイン状態が続きます)
- **誰にでも届くようにする方法**:Authentication → Emails の **SMTP Settings** で、自分たちのメールサーバー(Gmail のアプリパスワードなど)を設定する。本番公開するならこちらが必要です

> 北大のメールは、迷惑メールフォルダに入ることがあります。届かないときはそちらも確認してください。

## 5. 接続先を `config.js` に貼る

1. 左下の **Project Settings**(歯車)→ **API**(または Data API / API Keys)を開く
2. 次の2つをコピーする
   - **Project URL**(`https://xxxx.supabase.co`)
   - **anon public** キー(`eyJ...` で始まる長い文字列。「Legacy API keys」のタブにある場合があります)
3. GitHub の本家リポジトリで「アプリ本番用」の `config.js` を開き、鉛筆マークで編集する
   ```js
   window.NOKORI_CONFIG = {
     supabaseUrl: 'https://xxxx.supabase.co',
     supabaseAnonKey: 'eyJ......',
   };
   ```
4. Commit して、Fork で **Sync fork** を押す

> anon キーは公開してよいキーです(データの読み書きは、SQLで決めたルールで守られています)。
> **service_role / secret キーは絶対に貼らないでください。** 全データを自由に操作できてしまいます。

## 6. 動作確認(スマホ2台)

1. 2台とも公開URLを開き、下の「マッチ」タブ → 北大のメールアドレスを入力 → 届いた6桁の数字でログイン
2. プロフィールを作る
3. 「マッチ」をON、「空いている時間」を2人とも同じもの(例:今日の夜)にする
4. 期限が3日以内の食材を、それぞれの冷蔵庫に入れておく(例:Aは豚肉とキャベツ、Bはもやし)
5. 片方の「おすすめの相手」に、もう片方が出てくる → 「ごはんに誘う」
6. もう片方の「マッチ」タブに誘いが届く(15秒ごとに自動更新。タブを押し直すとすぐ更新)→ 「OK!」
7. メッセージと写真のシェアを試す

## このアプリが守っていること(発表・質疑用)

- **北大生だけ**:メールに届くコードでログインするので、北大のメールを受け取れる人しか登録できません。さらにデータベース側でも、`hokudai.ac.jp` 以外のアドレスの人は、何も読み書きできないようにしています
- **冷蔵庫の中身は見せすぎない**:相手に見えるのは、本人がマッチをONにしている間の、**期限が3日以内の食材だけ**です(期限切れの食材は共有しません)。ログアウトするとマッチはOFFになり、共有も消えます
- **性別は判定だけに使う**:「同性のみ」の判定はサーバーの中で行い、性別を非公開にした人の性別は、他の人のスマホには送られません
- **会話は定型文だけ**:マッチ成立後に送れるのは「向かっています」「少し遅れます」などの決まった文だけです。連絡先や住所のやりとりは、アプリ上ではできません
- **返事は本人だけ**:誘いに「OK/パス」できるのは誘われた本人だけ、取り消せるのは誘った本人だけ。内容の書き換えもできません
- **料理の実績**:ごはん会の写真の枚数がプロフィールに表示されます。料理が苦手な人どうしは、マッチしないようになっています

## 今後の課題(正直に言っておくとよいこと)

- ごはんの写真は、URLを知っている人なら見られる設定です。**料理だけを撮る**ようにしてください。本番では、北大生だけが見られる設定に変える予定
- 通報・ブロック機能はまだありません
- メールの送信は、本番では専用のメールサーバーの設定が必要です
